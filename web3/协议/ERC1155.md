## ERC1155
多代币标准，服务半同质化场景

## 数据结构
_balances：记录谁拥有多少某个代币   代币id -> 用户地址  
_operatorApprovals：记录授权关系     持有者地址 -> 操作者地址 -> 是否授权

## _updateWithAcceptanceCheck()
在update前校验接受方是否能接收代币(如果接受方是合约而不是普通用户)


## solidity
`/* id */`将id注释掉

`accounts.unsafeMemoryAccess(i),`直接读取 accounts 数组在内存中的第 i 个元素，跳过边界检查。省gas

`(uint256[] memory ids, uint256[] memory values) = _asSingletonArrays(id, value);`把单个 id 和 value 包装成单元素数组。

`to.code.length` 是目标地址的代码长度。
作用：判断 to 是普通地址（外部账户 EOA）还是合约地址。
普通地址：code.length == 0
合约地址：code.length > 0

```solidity
try 外部调用 returns (返回值) {
    // 成功时执行（调用没有 revert）
} catch {
    // 失败时执行（调用 revert 了）
}
```

先 _update 再校验，但 revert 能撤回转账。**整体回滚**

`assembly("memory-safe"){ }`告诉编译器这段汇编不会造成内存安全问题，更省gas
assembly表示里面写的是汇编代码
**汇编指令：**
`mload(地址)`：从内存中读取 32 字节数据
`mstore(地址, 值)`：将 32 字节数据写入内存
