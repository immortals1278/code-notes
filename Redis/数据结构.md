# 数据结构
## String
`set user:1001:name "Alice"`用set在缓存中添加键值对，用空格将键和值分开，可以用同样的语句覆盖已经存在的值

`get user:1001:name`用get根据键拿到值

`setex cache:user:1001 10 "cached_data"`添加的数据会在10秒后过期

`setnx lock:order:1001 "locked"`加锁，不可覆盖

`del lock:order:1001`删除

`set user:1001:name "Alice" NX EX 30`同时加锁和限时，时间为30s，可以自动释放锁

`INCR counter:page:views`递增，每执行一次键对应的值加一

`INCRBY counter:page:views 5`每执行一次加5

`DECR``DECRBY`递减同理
## Hash
```
HSET user:1002 name "Bob" age "30" email "123gmail.com"//可以一次设置多个字段

HGET user:1002 name
HGET user:1002 age
HGET user:1002 name age//批量获取

hgetall user:1002//可以一次获取所有字段和值

hdel user:1002 name//删除

hkeys user:1002//获取所有键
hvals user:1002//获取所有值

hlen user:1002//获取字段数量
```
#### 压缩列表
hash的一种编码方式。所有数据存储在连续的内存块中，根据数据大小动态选择编码方式，支持双向遍历
#### 哈希表
hash的一种编码方式。基于字典实现，通过指针连接的非连续内存，通过哈希计算来定位
## Set
```
SADD tags:article:1001 "redis"
SADD tags:article:1001 "database"//多次添加（添加重复成员返回0不添加）
SADD tags:article:1001 "golang" "web3"//批量添加

SMEMBERS tags:article:1001//查找

SREM tags:article:1001 "redis"//删除（可删除多个成员）

SISMEMBER tags:article:1001 "database"//判断是否存在,存在返回1
```
## 有序集合
```
ZADD leaderboard 100 "Alice"//根据分数大小排序（分数为100）
ZADD leaderboard 150 "Ben" 200 "Bob"//批量添加

ZRANGE leaderboard 0 -1//查看所有用户
ZRANGE leaderboard 0 1//可以指定范围

ZREM leaderboard "Alice"//删除


ZSCORE leaderboard "Bob"//获取分数

ZRANK leaderboard "Bob"//获取排名（从0开始）
```
## 缓存
### 基本用法
先查缓存，命中返回，没命中去查数据库，把数据库里的信息写到缓存，再返回给用户
### 缓存穿透
查询不存在的数据，导致每次请求都穿过缓存直接访问数据库，造成数据库压力

解决方法：
1. 缓存空对象，第一次查到空结果时设置一个60s过期的空值缓存，后面查询时就能直接返回空值
2. 布隆过滤器。查询前先判断数据是否存在不存在就不访问数据库。通过位数组和哈希实现，如果某一位全为1该数据可能存在，如果有一位是0那一定不存在
### 缓存雪崩
大量缓存在同一时间过期，导致大量请求同时访问数据库，造成数据库压力暴增

解决方式：
1.随机过期时间
### 持久化
将内存中的数据保存到磁盘，防止数据丢失
两种方式：RDB（redis database）和AOF（append only file）

AOF：数据完整性要求

RDB：恢复速度快，性能要求高
